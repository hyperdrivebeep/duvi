# E01 — 요청·반환과 로그 재생

도구를 한 번 실행한 것, 그 결과를 다시 읽은 것, 같은 답안을 다시 채점한 것은
서로 다릅니다. 주문표와 영수증을 번호로 맞추듯 호출과 반환을 연결하고, 증거가
부족할 때 답을 단정하지 않는 연습입니다.

**필수:** 1·3B·5단계 직접 수행 확인 뒤. 시간 상한 없이 독립 수행이 될 때까지
반복합니다. 저장소 루트에서 **Python 3.9+ 표준 라이브러리**만 사용합니다.
API·GPU·네트워크·npm 설치 없이 실습할 수 있습니다. 카드의 지정 발췌는
필요하면 미리 준비하세요. 앱은 이 코드를 자동 실행하지 않습니다.

## 학습 순서

1. `starter.py`를 같은 폴더의 `learner.py`로 복사하세요(또는 `starter.py`를
   수정하고 `--agent`를 생략). `solve`와 `Logger`는 상한·좌표·후보 예측만
   설정으로 받습니다. `solve`에는 도구 `measure(x)`, `submit(candidate)`도
   넘깁니다. 시드·실행 ID 등은 실행기가 로그를 저장할 때 붙입니다.
   후보 예측을 좌표별로 대조해 보세요.
   양수 전용 세계에서는 모든 후보가 일치하지만, 음수가 있는 세계에는
   후보를 가르는 좌표가 있습니다. 시작 상한은 턴 8회·측정 4회입니다.
   실패도 측정 시도 1회입니다. 제출할 턴을 남겨 두세요.
2. [스키마](SCHEMA.md)를 따라 `Logger.record`와 진단 목록을 구현하세요.
   `record` 인자에는 실제 입력·반환과 시점별 예산/종료가 들어 있습니다.
   정상/실패 로그를 만들고, 일시 오류만 최대 한 번 재시도하세요.
3. 생성한 ID의 로그를 재생·재채점하고 두 종류의 해시를 비교하세요.
   첫 행동을 바꾼 배열을 넣어 `diverged`를 확인하세요. 재생은 행동의
   변경 시점부터 과거 반환을 새 반환인 것처럼 제공하지 않습니다.
4. 최초 이상(행) / 수리로 확인한 원인 또는 원인 불명 / 최종 증상을 표로
   남기세요. 백본(이 키트에는 모델 없음) / 학습 목표 / 실행 설정(상한과
   실소비를 분리) / 과제 점수도 따로 적으세요.
5. 공개 세트 다음에는 튜터가 제출을 고정한 뒤 새 시드를 선택합니다.
   새 세트를 통과하고 처음 보는 로그를 도움 없이 설명하세요.
   검사에 실패하면 반례와 수정 내용을 기록하고 다시 시도하세요.

```sh
python -m exercises.e01 run exercises/e01/out/practice --agent exercises.e01.learner
python -m exercises.e01 grade exercises/e01/out/practice
python -m exercises.e01 replay exercises/e01/out/practice/RUN_ID.jsonl
python -m exercises.e01 rescore exercises/e01/out/practice/RUN_ID.jsonl
python -m unittest discover -s exercises/e01/tests -v
```

`RUN_ID`는 `run`이 출력한 파일명으로 바꾸세요. 분기 확인은
`[["measure",999]]`를 `out/actions.json`으로 저장하고 `replay`에
`--actions exercises/e01/out/actions.json`을 추가합니다. 단독 `rescore`는
과제 점수 재계산이고, `grade`는 재생·분기·채점 부작용까지 검사합니다.
참조 풀이가 필요할 때만 `--agent exercises.e01.solutions.reference`를 사용하세요.

CLI의 표준 출력과 오류 출력은 UTF-8입니다. Git Bash에서 다른 Python 명령에도
UTF-8 모드를 적용하려면 `export PYTHONUTF8=1`을 사용하세요
(PowerShell: `$env:PYTHONUTF8 = '1'`). 이전 PR 초안에서 만든 로그는
현재 스키마로 다시 생성하세요.

Duvi에는 현재 GitHub Actions 워크플로가 없어 CI에서 Python 실행이 보장되지
않습니다. `npm test`는 Python 3.9 이상을 찾으면 E01 검사도 실행하고, 없으면
해당 검사만 건너뜁니다. 건너뜀은 통과가 아니므로 위 Python 명령을 별도로 실행하세요.

### 용어

* **해시(hash):** 내용에서 계산한 비교용 지문. 정규화 해시는 JSON 공백·키
  순서 차이를 무시하지만 원본 해시는 파일 바이트 그대로를 비교합니다.
* **재생(replay):** 실제 도구를 다시 부르지 않고 저장된 요청과 반환으로 실행을 복원합니다.
* **분기(diverged):** 새 행동이 기록과 달라 복원을 중단했다는 뜻입니다.
* **재채점(rescore):** 같은 기록에서 점수를 다시 계산하며 원본은 바꾸지 않습니다.

## 통과 기준

* 정상·실패 요청과 반환이 각각 일대일. 일시 오류는 한 번 이하 재시도.
  같은 성공 호출의 재실행, 음수 예산, 종료 후 호출은 각각 0건.
* 오프라인 재생의 도구 호출 0회, 정규화 해시 동일. 행동 변경 시 `diverged`.
  재채점의 과제 점수와 원본 바이트 해시가 각각 일치.
* 주입된 오류는 실제 주입 증거를 담은 반환 행을 인용. 모호한 반환 행은
  원인을 추측해 확정하지 않고 **원인 불명**. 오류가 있는 두 세계에서 두
  종류의 오류를 실제로 관찰해 진단해야 함.
* 주어진 후보들에 대해 전체 허용 격자로도 구별할 수 없으면 보류.
  이미 증거가 충분하거나 허용 격자에 판별점이 있는데도 보류하면 탈락.
  제출 시에는 성공한 측정만으로 답이 하나로 좁혀져야 함.
* 공개·새 세트 연속 통과에 더해 아래 설명을 사람이 확인해야 최종 통과.

## 튜터: 평가 시점에 새 로그 생성

답안을 고정한 뒤 이전에 공개하지 않은 충분히 큰 무작위 정수 시드를 고르고 아래의 `SEED`를
대체하세요. 좌표·예측·후보 이름·숨은 답·ID가 달라질 수 있으며, 평가 턴은
6 또는 7, 홀수 시드는 오류 순서도 반대로 바뀝니다. 같은 시드는 재현 가능합니다.

```sh
python -m exercises.e01 evaluate exercises/e01/out/unseen --seed SEED --agent exercises.e01.learner
```

별도 설명용 로그는 다른 시드로 `run ... --seed SEED --agent
exercises.e01.solutions.reference`를 튜터가 실행해 만드세요. 로그는 커밋하지
않습니다. 새로운 *사례*이지 비밀 시험 서버는 아닙니다. 공개 코드와 시드를
읽을 수 있는 사람을 대상으로 정답을 보안 격리하지 않습니다.
