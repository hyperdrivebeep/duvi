# E01 진단 평행형 및 사람 채점표

## 출제 전 — 튜터 또는 자기 감독 학습자

1. 시점마다 신규 시드를 뽑으세요(저장소 루트에서
   `python -c "from secrets import randbits; print(randbits(63))"`). 사전·사후·지연,
   완료검사의 두 세트 및 별도 설명용 시드는 서로 달라야 합니다. 사후와
   완료검사 시드는 코드 지문을 고정한 다음 뽑으세요. 재현/도구 확인용
   예시 시드는 `2026112601`, `2026112602`, `2026112603`입니다. 실측에는 사용하지 마세요.
2. 사람 튜터는 출제 후 조건과 정답을 아래 방식으로 독립 확인합니다.
   검사지의 시드로 `assessment key`를 실행하면 정답을 볼 수 있습니다.
   튜터가 있다면 `assessment form ... --hide-seed`로 시드 없는 검사지만
   전달하고 시드는 튜터가 따로 보관하세요. 이는 보안 격리가 아닙니다. 자기
   감독이라면 미리 시드·파일명·검사 규칙만 기록하고, 항목·정답 검증은 해당
   답안을 고정한 뒤 하세요. 검증에 실패한 형식은 사유와 함께 무효로 남깁니다.
3. 완료검사 조건 비교에는 `python -c "from exercises.e01.fixtures import suite; print([{k:c.config[k] for k in ('points','predictions','turns','measurements')} for c in suite(SEED)])"`
   를 쓰세요. `SEED`를 실제 정수로 바꾸고 공개 세트에는 `None`을 넣으세요.
   두 새 세트 각각이 공개 세트 및 서로와 비교해 후보 표·좌표·턴 중 하나
   이상이 달라야 합니다(시드·ID만 다른 것은 불충분). 튜터만 미리 점검하거나
   자기 감독이면 실행 후 확인하세요. 겹치면 무효 사유를 기록하고 새 시드로 대체하세요.

### 한 문항은행, 세 평행형

`assessment form --seed SEED --output 경로`가 실제 문항과 빈 답안 틀을 만듭니다.
동일 시드·도구 버전은 같은 형식을 재현합니다. 사전·사후·지연의 구성이
같으며, 사례·후보·짝 대상·출력 순서 등은 시드에 따라 달라집니다. 객관
문항은 요청·반환의 연결, 재생·재채점, 원인 근거, 보류 판단의 작동 원리를
이해했는지 확인하는 진단입니다. 난도 동등성이나 반복 연습 효과를
검증하지 않았습니다. 실제 숙련은 별도의 조건 변경 세트 두 개를 연속
통과하고 사람이 처음 보는 로그의 독립 서술을 판정해야 확인됩니다.

| 항목 | 구체 문항과 응답 형식 | 객관 점수 | 사람이 독립 확인할 근거 |
| --- | --- | --- | --- |
| `pair` | 재시도에 대응하는 반환의 목록 번호 `line`(정수) | 0–1 | 같은 실행 안에서 재시도 `call_id`·`tool`·`input` 및 바로 다음 `seq`를 대조. 다른 실행에도 같은 `call_id`가 있음 |
| `operation_A/B` | `replay` 또는 `rescore` | 각 0–1 | 실제 도구 호출과 원본 변경 여부를 확인하고, 같은 기록의 정규화 지문이 재생에서만 재현되고 첫 입력 변경으로 분기하는지 대조 |
| `fault_1/2` | 객체의 `seq`에 근거 반환 행 번호(정수), `label`에 `주입된 일시 오류` 또는 `원인 불명` | 각 0–1 | 요청에 대응하는 반환과 같은 `ref`를 감사 기록에서 찾아 주입 여부 확인. 근거 반환 행과 라벨이 모두 맞아야 1점 |
| `defer_A/B` | `정당` 또는 `불필요` | 각 0–1 | 성공 관측으로 남은 후보와 전체 허용 좌표에서의 예측 차이. 좌표의 부호는 판정 기준이 아님 |
| `explanation` | 별도 로그를 읽고 문항 안의 ①②③에 자기 말로 답변 | 사람 0–3 | 아래 서술 기준 |

## 답안을 고정한 뒤 — 객관 정답·자동 채점

파일을 저장하고 `git hash-object exercises/e01/out/pre.answers.json`으로 답안
지문을 기록하세요. 아래 `SEED`는 해당 검사지에 쓴 시드(튜터가 보관했으면 튜터 기록)입니다.
사후·지연은 출력 경로의 `pre`도 각각 `post`, `retention`으로 바꾸세요.

```sh
python -m exercises.e01 assessment key --seed SEED
python -m exercises.e01 assessment score --seed SEED exercises/e01/out/pre.answers.json --output exercises/e01/out/pre.score.json
```

키는 기존 사례를 참조 풀이로 실행하고 로그를 본 채점기로 검증한 뒤
자동 생성합니다. 짝은 검증된 로그에서, 작업 유형은 실제 `replay`/`rescore`
실행에서, 오류의 근거 행·라벨과 보류 판정은 본 채점기의 `trace_score`에서 가져옵니다.
정답은 AI가 쓰거나 고르지 않습니다. 사람은 표의 근거를 문항 자료에서
직접 대조해 승인하세요. 자료와 기계 키가 충돌하면 이유를 기록하고 해당
형식은 비교에 쓰지 않습니다. 점수는 정답마다 1점(빈칸·오답 0, 부분점수 없음).
대소문자와 숫자/문자 형식을 그대로 쓰고, 문자열 바깥 공백만 무시합니다.

회귀 테스트는 200개 시드에서 상태명·출력 키·호출 ID·좌표 부호만 쓰는
네 가지 규칙을 적용합니다. 각 유형과 전체 득점률 상한은 60%입니다.
이진 선택의 기준선인 50%에 시드 표본 변동 여유 10%p를 더하되,
특정 유형의 높은 득점률이 전체 평균에 가려지지 않게 합니다. 이 검사는
알려진 지름길만 검사하며, 암기 저항성이나 학습 효과를 입증하지 않습니다.

## 사람 채점 — 설명 0~3점

각 기준 전부를 서술하고 실제 로그 근거를 댔으면 1점, 그렇지 않으면 0점입니다.
말투보다 내용과 근거를 봅니다. 보완 질문으로 답을 유도해 점수를 올리지 않습니다.
가능하면 같은 사람이 시점 표기를 가린 채 세 답안을 같은 기준으로 판정합니다.

| 기준 | 1점 | 0점 예 |
| --- | --- | --- |
| ① 호출·예산 | 요청과 실제 반환을 행 번호 또는 호출 ID로 연결하고 남은 턴·측정 예산을 설정 상한과 구별 | 두 행을 연결하지 못하거나 상한을 남은 예산으로 읽음 |
| ② 고정·변경 | 같은 로그·설정을 고정해 실제 도구를 다시 부르지 않는 재생을 설명하고, 첫 입력 999로는 기록과 달라 `diverged`하여 과거 반환을 쓰지 못함을 첫 요청 행에 연결 | 재생을 새 측정이나 재채점과 같다고 설명 |
| ③ 근거·범위 | 후보를 실제로 가르는 성공 반환 행과 좌표·예측표로 결론을 설명하고 허용 후보·격자 안에서만 주장 | 제출 수신 확인을 정답 증거로 쓰거나 전체 세계로 일반화 |
