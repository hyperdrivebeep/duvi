# E01 학습자 진행·측정 절차

이 문서는 **측정 준비**입니다. 실제 사람이 직접 풀고 시간을 기록하고 서술을
판정하기 전에는 소요 시간도 학습 효과도 측정되지 않았습니다. 12–18시간은
시작 추정치일 뿐 상한이 아닙니다. 주 10–12시간을 공부한다면 여러 날로 나누고,
필요한 만큼 반복하세요. 시간이나 AI의 승인만으로는 완료되지 않습니다.

## 1. 시작 전에

- **학습자:** 로드맵의 1·3B·5단계를 직접 수행했는지 확인하세요. 저장소 루트의
  터미널에서 `python --version`(3.9 이상), `python -m exercises.e01 --help`를
  실행하세요. 폴더 이동, 파일 복사, JSON 파일 열기와 저장을 먼저 해 보세요.
  리스트·딕셔너리·`if`·`for`가 낯설다면 E01 사례가 아닌 예제로 연습하고,
  충족 여부와 사전 노출을 기록하세요. E01 풀이·공개 로그·정답은 사전 검사 전 열지 마세요.
- **사람 튜터(권장) 또는 학습자 본인:** 시험을 감독하고, 배정한 시드와 코드
  지문을 기록하고, 답안 고정 뒤에만 정답과 루브릭을 대조하세요. 혼자라면
  선답·후채점 원칙을 지키고 자기 채점임을 적으세요. AI는 연습 중 요청받은
  도움을 제공할 수 있으나 시험 변수나 정답을 독자적으로 정하거나 서술 점수와
  독립 수행 여부를 확정하지 않습니다. AI의 문구·채점 제안은 **비권위적 참고**
  입니다. 사람의 근거 확인이 없으면 해당 판정은 `미검증`입니다.

## 2. 사전 검사 — E01 연습 전에

튜터가 [평가 문항·채점표](ASSESSMENT.md)의 절차로 새 시드를 배정해 검사지를
만듭니다. 예를 들어 명령의 `PRE_SEED`는 배정된 숫자로 바꾸세요.

```sh
python -m exercises.e01 assessment form --seed PRE_SEED --output exercises/e01/out/pre.form.json
python -m exercises.e01 log start pre
```

학습자는 파일의 `items`를 열어 한 번씩 풉니다. `answer_template` **객체만**
별도 `exercises/e01/out/pre.answers.json`에 복사하고 값을 채우세요. 모르면
`null`로 남겨도 됩니다. `fault_1`, `fault_2`에는 각각 근거 행 번호(`seq`)와
원인 라벨(`label`)을 채우세요. 자유 서술은 한국어 문장 하나의 JSON 문자열로 적거나
초안을 텍스트 파일에 쓴 후 붙여 넣으세요. 미리보기·검색·풀이·도움·코드 실행
없이 파일 읽기와 메모만 허용합니다. 세 검사 모두 같은 규칙으로, 약 20분을
잡되 강제로 끊지 말고 실제 시간을 적으세요. 답안을 저장하면 도움 유무를
기록하고 `log stop`을 실행하세요. 검사 후 정답은 지연 검사 답안을 고정할
때까지 학습자에게 공개하지 않습니다. 진단 점수는 E01 진입 컷이 아닙니다.

## 3. 직접 연습 — README 1~5단계

| 기록 단계 | README | 학습자가 직접 할 일 |
| --- | --- | --- |
| `setup` | 1 | `starter.py`를 `learner.py`로 복사. 후보 두 개의 예측을 손으로 비교하고 예산과 제출할 턴을 표시. |
| `implement` | 2 | `Logger.record`, `solve`, 진단을 작은 단위로 구현. 정상·오류 로그에서 요청/반환과 예산 확인. |
| `replay` | 3 | 같은 로그의 재생·재채점을 각각 실행. 첫 행동을 바꾸어 `diverged` 확인. 재생의 정규화 해시와 재채점 전후 원본 해시를 구별. |
| `diagnose` | 4 | 최초 이상 행 / 수리 근거 또는 원인 불명 / 최종 증상과, 목표·설정 상한·실소비·과제 점수를 따로 적기. |
| `mastery` | 5 | 공개 채점을 확인하고 제출 지문을 고정. 처음 보는 두 조건 변경 세트와 별도 로그 설명에 독립적으로 응시. |

막히면 먼저 **예상 → 실제 → 처음 다른 행**을 한 줄씩 쓰세요. 예를 들어
짝이 안 맞으면 `call_id`와 `tool`/`input`, 예산이 이상하면 실패도 차감되는지,
보류가 틀리면 **아직 안 쓴 허용 좌표**의 예측 차이를 확인하세요. 10–15분 정도
혼자 확인해도 모르겠으면 문제를 한 줄로 좁히고 힌트 하나만 요청하세요. 그래도
필요해 풀이를 열면 그렇게 기록하고, 닫은 뒤 작은 사례에서 처음부터 재시도하세요.
환경 문제 또는 긴 중단은 시간을 끊어 별도 메모로 남기고 0분으로 꾸미지 않습니다.

### 실제 시간과 도움 기록

작업을 시작·재개하거나 단계가 바뀔 때 `start 단계`, 멈출 때 `stop`을 실행합니다.
아래 명령은 **사용 방법 예시**이며 실제 그 행동을 한 경우에만 실행하세요.

```sh
python -m exercises.e01 log start implement
python -m exercises.e01 log note --help-level hint --text "요청·반환 중 어느 열을 볼지 힌트"
python -m exercises.e01 log note --attempt public-01 --outcome fail --text "grade: pairing 2번 호출 불일치"
python -m exercises.e01 log stop --reason break
python -m exercises.e01 log summary
```

- 실작업은 읽기·생각·코딩·실행·결과 해석을 포함합니다. 식사·전화·방치한
  실행 대기 등은 포함하지 않습니다. 휴식은 `stop --reason break`, 돌발
  중단은 `stop --reason interruption`으로 닫고, 재개 때 `start` 후
  `note --text "중단 이유…"`로 연결하세요. 언제 멈췄는지 잊어 구간을 신뢰할
  수 없으면 `stop --reason uncertain`으로 제외하고 누락으로 보고하세요.
- 도움을 받는 즉시 `note --help-level`로 기록합니다. 받지 않은 구간에는
  닫기 전 `note --help-level none`을 남기세요. `hint`는 방향만 받은 사람
  힌트, `solution-peek`은 해답/완성 코드 열람, `AI-help`는 AI 도움입니다.
  AI의 완성 답안도 보았다면 두 사건을 각각 기록하세요. 무기록은 `none`이
  아니라 미상입니다. 단계가 넘어가도 도움·시도 기록을 지우지 않습니다.
- `grade`/`evaluate` **한 명령 실행당** 유일한 `--attempt` ID 한 개를 쓰세요.
  모든 사례 `PASS`와 종료 코드 0은 `pass`, 루브릭/채점기 기준 위반은 `fail`,
  환경·실행 문제로 판정 불능이면 `error`입니다. `--text`에 명령 종류,
  시드 또는 공개 세트, 나온 PASS 수나 첫 실패 기준을 간단히 적으세요.
  요약은 이를 자동 집계하지만 실제 채점 출력은 사용자가 정확히 옮겨 적습니다.
- [세션 스키마](SESSION_SCHEMA.json): 한 줄에 이벤트 하나, 로컬의
  `exercises/e01/log/sessions.jsonl`에만 저장합니다. 한 번에 터미널 하나에서
  사용하고 시스템 시간을 바꾸지 마세요. 닫힌 유효 구간의 `stop − start`만
  합산하며 미종료·불확실 시간은 빠집니다. 요약의 도움 수준별 세션 수는
  한 구간에 여러 도움이 있으면 중복 집계됩니다. 이 숫자는 자기 기록이며,
  클릭 감지나 출석 확인이 아닙니다. `--synthetic`은 별도 QA 저널입니다.
  실습에는 쓰지 말고 개인정보·원본 세션·답안은 Git이나 공개 PR에 올리지 마세요.

## 4. 완료 검사 — 같은 고정 코드로 새 세트 두 번

1. **학습자:** 공개 `grade`를 통과한 뒤 코드 수정과 도움을 중단합니다. 튜터에게
   고정본과 지문을 넘기세요. 단일 파일이라면 `git hash-object exercises/e01/learner.py`;
   보조 파일이 있다면 함께 스냅샷을 만들고 각각의 지문도 적습니다.
2. **사람 튜터:** 코드가 고정된 뒤 새 시드 두 개를 별도로 뽑고, 이전에 본
   시드와 중복되지 않는지 봅니다. 후보·측정 조건이 실제 달라졌는지 확인하세요
   ([검증 방법](ASSESSMENT.md)). 학습자가 도움 없이 각 세트에서 다음 명령을
   실행하고 출력, 시드, 지문을 기록하게 하세요. 실제 숫자로 `SEED_A`/`SEED_B`를 바꿉니다.

   ```sh
   python -m exercises.e01 evaluate exercises/e01/out/mastery-a --seed SEED_A --agent exercises.e01.learner
   python -m exercises.e01 evaluate exercises/e01/out/mastery-b --seed SEED_B --agent exercises.e01.learner
   ```

3. **사람 튜터:** 새 시드 `EXPLANATION_SEED`로 별도 로그를 생성하세요.
   `python -m exercises.e01 run exercises/e01/out/unseen-explanation --seed EXPLANATION_SEED --agent exercises.e01.solutions.reference`
   를 실행해 오류가 있는 사례의 `.jsonl`과 해당 `.config.json`만 보여 주세요.
   학습자는 도움 없이 [README의 세 질문](README.md#자유-서술-판정표-사람-또는-튜터)을
   모두 행·설정 근거를 들어 설명합니다. 자동 채점기가 이 부분을 대신할 수 없습니다.
4. 같은 고정본으로 서로 다른 조건 세트 **두 번 연속 전 사례 통과** 및 새로운
   로그의 **세 설명 기준 모두 충족**, 그리고 사람 확인이 완료 기준입니다.
   중간 실패, 수정, 도움, 사전 노출이 있으면 기준을 충족하지 못한 시도를 보존하고
   연습으로 돌아갑니다. 새 고정본이면 새 시드 두 개로 연속 기록을 다시 시작합니다.

## 5. 사후 검사와 1–2주 뒤 지연 검사

- **사후:** 완료 검사 후(중도 종료했다면 그 사실과 최종 상태를 기록) 현재
  코드 지문을 다시 확인합니다. **고정 후** 아직 쓰지 않은 `POST_SEED`로 평행형을
  만듭니다. 사전과 같은 방식으로 `post` 시간을 기록하고 답안을 고정하세요.
- **지연:** 사후 검사일에서 **7–14일 뒤** 약속을 잡습니다. 그동안의 복습·추가
  연습을 따로 기록하고, 당일 시험 직전 예열 없이 새 `RETENTION_SEED`로
  `retention` 시간을 기록합니다. 못 했다면 `미실시`로 표시하고 0점을 넣지 마세요.
- **자동:** 시드로 문항·정답 재생성 및 객관식 채점. **사람:** 사전 대비
  조건이 같은지, 독립 수행인지, 서술이 근거를 갖췄는지 판정합니다. 비교
  가능성을 해친 도움·시간·재시도·시드 노출은 점수와 함께 공개하세요.
