# Duvi 학습·탐구 설계와 구현 범위

수정일: 2026-11-16. 아래의 **구현됨**은 현재 작업 트리의 소스에 기능이 있다는 뜻이다.
자동 테스트 통과, 실제 브라우저 동작, 실제 AI 서비스 응답, 학습자의 이해는 별개의 증거다.
병렬 구현 중인 작업 트리이므로 통합 확인 항목을 완료 기능으로 간주하지 않는다.

## 남은 구현과 통합 확인

- 튜터 화면 요청은 저장된 `recordId`, `mode`, 선택 `model`을 사용하도록 통합되었다.
  모드는 `hint/critique/explain`이다. 소스 계약 일치와 실제 계정 요청 성공은 다르므로
  저장→문맥 확인→명시 전송→응답·도움 정도 저장의 라이브 흐름은 별도 확인한다.
- 기록 편집기의 AI 도움은 응답 전문을 저장하지 않고 도움 정도만 남긴다. 질문 탭의 대화와 완료된 답
  (`aiAnswer`)은 강의별로 저장한다(2026-11-24 자동 기록 참고).
- 아래 목표의 별도 EvidenceCard/RivalHypothesis/DiscriminatingTest/ExperimentLink 객체,
  원문 hash와 자동 재연결, 구조화된 연구 연결·자동 발행은 미구현이다. 현재는 선택 텍스트 필드다.
- 실습 코드 실행·결과 자동 검산·새 문제 독립 수행 평가·숙달 자동 승격은 구현하지 않았다.
  외부 노트북은 사용자가 실행하고 결과와 한계를 기록한다.
- 실제 브라우저에서 첫 클릭→강의→저장/재로드→복습→백업/복원 흐름, 작은 화면/전체화면,
  재생·정렬 자막 유지와 실제 계정 AI 응답은 이 문서 작업에서 실행하지 않았다.
  아래 검증 시나리오는 확인해야 할 항목이며 성공 기록이 아니다.

## 목적

사용자가 강의를 이해하고, 그 설명의 관측·선택·변수·가정을 확인한 뒤,
대안과 판별 실험을 제안하고 자신의 생각을 수정하는 능력을 키운다.
[Glorious 북극성](https://github.com/hyperdrivebeep/glorious-purpose/blob/a42be23ebd99a511e8ddcfd6baac5c592cbe0aa4/PROJECT_WIKI/00_DIRECTION/NORTH_STAR.md)을 지원한다.

폴더/재생목록/문장별 반복/영한 정렬 자막/집중 보기를 바탕으로 학습 기능을 확장한다.
완강이나 AI의 긍정 판정을 과학적 이해와 동일하게 취급하지 않는다.

## 첫 학습 경로와 정본

첫 클릭은 **학습 로드맵 → MIT 1강 시작하기**.
첫 본강의는 Duvi “MIT Python 기초”의 Lecture 1. 그다음 Lecture 2, 3 순서.
Stanford CS229 LLM 영상은 도입8분만 개관용으로 먼저 볼 수 있다.
세부 강의 순서·첫2주·53주 편성·연장/통과 기준은
[강의별 로드맵](https://github.com/hyperdrivebeep/glorious-purpose/blob/a42be23ebd99a511e8ddcfd6baac5c592cbe0aa4/PROJECT_WIKI/10_RESEARCH/DISCOVERY_LEARNING_ROADMAP.md)에 둔다.
앱의 `src/learning-roadmap.mjs`는 해당 정본의 URL/commit/확인일을 명시한 스냅샷이다.
독립적인 새 일정을 만들지 않으며 정본 변경 시 출처 버전과 내용을 함께 갱신한다.
확인 방식의 한계도 표시한다. 링크/제목 확인은 전체 영상 시청·자막 대조를 의미하지 않는다.

`npm run setup` 이후 `npm run prepare:learning`을 실행하거나 화면의
**순서대로 강의 폴더 준비**를 사용한다. CLI의 `--root <backend-directory>`는
이미 MIT 데이터가 있는 별도 backend 경로를 지정한다. 기존 자료와 이름을 재사용하고,
커리큘럼 순서를 맞춘 뒤 사용자 추가 강의를 보존한다. 학습 완료 상태는 만들지 않는다.

## 사용자 흐름

강의 보기 → 막힌 시점 저장 → 내 설명 → 근거/가정 구분 → 대안·판별 질문 → 작은 실습 → 생각 수정 → 지연 복습.

처음에는 질문 한 줄만 저장할 수 있다. 다음 칸을 전부 채워야 저장되는 폼을 만들지 않는다.
학습자는 내용 이해 후 선택적으로 “이 설명을 시험하기”를 열어 관측/가정/대안을 추가한다.
초보자에게 모든 강의를 반박하거나 새로운 이론을 발명하도록 요구하지 않는다.

예: Python 조건문을 배운 뒤 교육용 모의 측정값 [1..10]에서 5 이상만 남기면 평균이 5.5에서 7.5로 달라진다.
측정값의 오류 없이 선택 규칙만으로 결론이 달라짐을 이해한다. 다음에는 원시 목록을 주지 않고
“선택된 값만으로 원래 평균을 확정할 수 있는가?”를 묻는다. 정답을 모를 때의 보류도 학습한다.

## 현재 데이터 계약과 확장 목표

현재 저장 형식은 `schemaVersion: 1`, 전역 `revision`, `records`, `progress`, 빈 `settings`다.
기록은 stable ID, 자체 revision, 생성/수정 시각, 최초 설명, 수정/복습 이력과 선택 텍스트 필드를 갖는다.
현재 anchor는 `lectureId/seconds/sourceText/translation/cueStart/cueEnd/alignmentRevision`이다.
UI는 원문·cue 범위·정렬 revision 일치를 확인하고 불일치 시 다른 문장으로 조용히 이동하지 않는다.

아래 별도 객체와 hash 기반 anchor는 확장 목표다. 현재 텍스트 필드가 이를 모두 구현한 것은 아니다.

기존 계획의 Goal/Competency/ResourceSegment/Question/Attempt/Review/ExperimentLink/SourceSnapshot을 유지한다.
큰 전역 지식 그래프나 별도 플랫폼을 먼저 만들지 않는다. 카드별 선택 필드로 시작한다.

- EvidenceCard: 관측값/단위/범위/측정 방식, 원자료 출처, 선택·결측·전처리, 변수·대리 지표, 해석과 가정.
- RivalHypothesis: 기존 설명/대안/측정오류 종류, 예상 결과, 가정, 현재 자료로 구별 가능 여부.
- DiscriminatingTest: 조건/행동, 각 후보의 예측, 필요한 추가 정보, 도구·비용, 사전 성공/실패 기준.
- Revision: 이전 생각/새 생각, 바꾼 증거, 보류 이유. 기존 관측의 재해석과 새로운 측정의 획득을 구분.
- LearningChange: context/posterior/candidates/weights/cross-task-memory 중 무엇이 변했는지.
- SourceSnapshot: 원문 URL/시간/문서 SHA/확인 방식/상태. AI 작성 설명과 저자의 주장을 분리.
- 공통: stable ID, schemaVersion, revision, createdAt/updatedAt. 사용자가 쓰지 않은 칸은 빈 값/미확인.

원시 자막은 보존한다. anchor는 lectureId+시간+cue/text hash+alignmentRevision을 사용하고,
재정렬/삭제 후 연결을 복원할 수 없으면 미연결 표시를 한다. 다른 문장에 조용히 연결하지 않는다.

## 튜터와 평가

AI는 “다른 설명을 생각해 볼까?”뿐 아니라 “기존 설명을 유지해야 하는 증거는?”도 묻는다.
반대 의견이나 참신함 자체에 점수를 주지 않는다. 원문 근거·반례·계산·독립 확인으로 평가한다.
모르는 관측값이나 실험 결과를 생성해서 사실처럼 채우지 않는다.
채점은 source-grounded/계산 확인/자기 평가/AI 제안/사람 검토를 구분한다.
AI 점수만으로 숙달을 승격하지 않는다. 사용자가 요청할 때만 필요한 문맥을 기존 인증 경로로 전송한다.
현재 서버는 저장된 기록의 텍스트 필드·도움 정도·일치한 원문 구간을 보낸다.
화면의 전송 미리보기는 이 실제 payload 범위와 일치해야 하며, 질문·설명만 보낸다고 축소 안내하지 않는다.
API가 없어도 기록·복습·내보내기는 가능해야 한다.

복습 1/3/7일은 조정 가능한 초기 기본값이며 보편적 최적 간격이라는 연구 결론이 아니다.
교육용 실습/탐색 기록과 확증 연구의 사전 계약을 구분한다. 모든 메모에 실험 사전등록을 강요하지 않는다.

## 구현 순서와 경계

- 먼저 저장 계약/backup schema와 source anchor를 확정한 뒤 질문·설명·근거 카드.
- 그다음 대안/판별/실습·복습, 이후 Glorious 내보내기와 AI 도움.
- UI 통합 및 백업 roundtrip 검증으로 마무리. 기능별 구현과 직접 테스트를 같은 작업 단위로 묶는다.
- backend의 atomic JSON·직렬화 저장 패턴 활용. 같은 revision 동시 수정은 충돌 응답으로 처리.
- import는 버전/타입/크기/중복 ID/경로를 검증하고 미리보기·백업 뒤 반영.
- 기존 같은 출처/CSRF/본문 제한을 유지. JSON/Markdown/강의 문장을 실행 명령으로 취급하지 않는다.
- 실습은 로컬 notebook/파일 링크와 결과 첨부로 연결. 웹 페이지에서 임의 셸 실행 기능을 추가하지 않는다.
- 학습 기록과 토큰/쿠키는 Git에 올리지 않는다. 외부 문서 발행·GitHub push는 자동 학습 동작이 아니다.

## 검증 시나리오

`npm test`는 Vite/Sites 사전 빌드 후 기존 테스트와
`backend/tests/learning*.test.mjs`, `tests/learning-ui*.test.mjs`를 함께 실행한다.

## 완료 표시와 다음 학습 (2026-11-17)

강의를 마쳤으면 목록의 원형 버튼 또는 재생 제어의 **강의 완료**를 누른다.
목록에 체크와 완료 문구가 나타나고, 단계별 완료 수·진행률 및 다음 학습 안내가
함께 갱신된다. 다시 누르면 취소된다. 같은 강의를 여러 폴더에 넣어도 완료는 공유한다.

단계 진행률은 로드맵에 등록된 영상·읽기·실습 자료 중 완료 표시한 자료의 비율이다.
3·5D·8단계처럼 영상이 없는 단계는 과제 수와 **읽기·실습 보기**를 표시한다.
자료는 원래 사이트에서 공부하고 로드맵에서 완료를 표시한다. Duvi에 문서를 임베드하거나
실습 코드를 실행하지 않는다. 로드맵 밖에 직접 추가한 강의의 완료도 저장하지만,
그 강의를 정규 로드맵 진행률의 분모에 자동으로 넣지는 않는다.

**학습 중 / 직접 실습 중 / 내 말로 설명함 / 시간을 두고 적용함**은 완료와 별개다.
기존 활동 기록을 자동으로 완료로 바꾸지 않는다. 다음 학습은 미완료 자료 중
학습·실습 중인 자료를 우선하고, 없으면 로드맵 순서를 따른다. 모두 완료하면 복습을 안내한다.
시청 시간, 자막 이동, AI 응답은 완료나 숙달을 자동으로 판정하지 않는다.

완료 상태는 이 PC의 학습 저장소와 학습 백업에 포함된다. 다른 PC에서는 최신 코드를
받은 뒤 **학습 로드맵 → 백업·복원**으로 학습 백업을 옮긴다. GitHub push는 개인 학습
진행률을 동기화하지 않는다.

## 앱 틀 A와 질문 자동 기록 (2026-11-24)

사용자 결정: 재설계 시안 A(이동 레일 + 강의 + 옆 패널)를 앱의 틀로 쓰고, 시안 C의 개념 지도와 진척 표를
개념 지도 화면으로 쓴다. 질문은 보내는 순간 기록된다.

- 화면: 모든 화면 왼쪽에 같은 이동 레일(강의, 개념 지도, 확인 문제, 돌아보기, 설정)이 있다. 내 강의 목록은
  강의 머리줄의 **☰ 내 강의**로 여는 패널이다. 강의 화면의 오른쪽 패널(372px, 전체화면 380px)에는
  질문 / 개념 / 확인 문제 / 대본 탭이 있다. 기록 탭과 학습 탭은 없앴고, 학습 탭에 있던 다음 할 일·
  로드맵·내 기록·복습·백업·현재 시점 기록 남기기는 돌아보기 화면으로 옮겼다.
- 자동 기록: 질문을 보내면 서버가 그 질문과 학습 기록을 한 번에 저장한다. 기록의 시각은 입력을 시작한 때의
  재생 시각이고, AI 답은 완료되었을 때만 `aiAnswer`로 붙는다(멈춤·끊김·실패면 비어 있다). 같은 질문 ID로
  다시 보내면(다시 묻기, 응답을 못 받은 재전송) 질문과 기록을 새로 만들지 않는다.
- 복습(사용자 확인, 2026-11-24): 자동으로 기록된 질문은 학습자가 내 설명을 쓰기 전까지 복습 날짜가 없다.
  첫 내 설명을 저장하면 다음 날 복습이 잡힌다. 그래서 질문만 한 것은 "열린 질문"으로 남고 복습 목록을
  늘리지 않는다.
- 상세 편집: 근거·가정·대안·예측·결과·생각 수정, 최초 설명·수정 이력, Markdown, AI 도움은 질문 아래
  **자세히**로 여는 대화상자에 그대로 있다.
- 튜터에 보내는 "이 강의 내 노트"에는 채팅에서 자동 기록된 질문 중 내 설명이 있는 것만 들어간다. 질문 자체는
  이미 대화로 전달되기 때문이다.
- 데이터: 학습 상태 스키마는 바꾸지 않았다(v2는 이미 모든 메시지의 `recordId`를 허용). 백업·복원과 폴더
  동기화는 그대로다.
- 아직 없음: 개념 지도, 강의별 개념, 확인 문제, 증거 기반 돌아보기는 자리(`#view-map`, `#view-quiz`,
  `#view-review`, `#lectureConcepts`, `#lectureQuiz`)와 "준비 중" 안내만 있다.

## 확인 문제와 돌아보기 근거 (2026-11-24)

구현 범위는 백엔드와 화면 모듈이다(`backend/learning-quiz.mjs`, `backend/python-runner*.mjs`,
`backend/learning-sources.mjs`, `backend/learning-evidence.mjs`, `src/quiz-view.mjs`, `src/review-view.mjs`).
앱 셸에 붙이는 작업과 실제 ChatGPT 계정으로 만든 문제의 품질은 이 작업에서 확인하지 않았다.

- **만들기**: 학습자가 10분 구간을 고르고 **보낼 자료 확인**을 눌러 실제로 보낼 내용(영어·한국어 정렬 대본,
  선택한 저장소·위키 발췌의 경로와 줄 범위, 개념 이름)을 본 뒤 **보내고 만들기**를 눌러야만 내 ChatGPT 연결로
  보낸다. 미리보기 토큰은 10분 유효하고 실패하면 같은 입력으로 다시 시도할 수 있다. 결과는 번역처럼 생성 자산
  `backend/quizzes/<강의>.json`(Git 제외)에 구간별 대본 hash·정렬 revision과 함께 저장하고, 자막이 바뀌면
  "예전 대본 기준"으로 표시한다. `DUVI_CHAT_MOCK=1`의 모의 문제는 QA 전용이다.
- **정답 근거**: `executed`(정답: 실제 실행 결과) · `source_quoted`(원문 인용 확인) · `learner_confirmed`(내가 확인)
  · `ai_unverified`(AI 제안 · 정답 미검증) · `retired`(신고해 뺌). 인용은 대본 구간이나 인용한 파일 줄에
  글자 그대로(공백 차이만 허용) 있어야 통과한다. AI만 정한 답은 검증으로 바꾸지 않는다.
- **실행 경계**: 실행하는 것은 생성된 문제에 들어 있는 고정 Python 코드(`code`)뿐이고, 세트를 만들 때 한 번만
  Pyodide(WebAssembly)로 실행한다. 문제마다 새 worker thread, 불러온 뒤 3초 강제 종료, 출력 4,000자 제한,
  메모리 안의 기본 파일 시스템만 쓰며 `js`·`pyodide`·`micropip` 같은 JavaScript 연결 모듈은 지우고 import를 막는다.
  실제 출력이 AI 예상 답과 다르면 실제 출력을 정답으로 쓰고 불일치를 기록한다. 시간 초과나 Pyodide 로딩 실패는
  `ai_unverified`와 이유로 남는다. **학습자가 쓴 답·설명은 어떤 경우에도 실행하지 않는다**(실행되는 입력 칸이 없다).
  import 차단은 JavaScript로 나가는 길을 막는 방어 장치이지 검증된 보안 격리(sandbox)가 아니다. 그래서 실행 대상을
  생성된 문제 코드로 한정한다.
- **푼 기록**: 학습 상태 schema 3의 `attempts`. 문제 스냅샷, 예측, 확신(낮음/보통/높음), 결과, 채점 방식(보기 자동
  /내가 채점), 내 설명, 근거 상태 스냅샷, 다음 복습. 틀림(확실했는데 틀림 포함) 1일, 맞았지만 확신 낮음·보통 3일,
  확실히 맞음 7일. 백업·동기화는 기록처럼 ID 단위로 합치고 설명은 나중에 고친 쪽을 쓴다. schema 2 이하 파일은
  빈 `attempts`로 올라가며, schema 2만 아는 PC는 새 파일을 읽지 못하므로 두 PC 모두 새 버전이 필요하다.
- **읽기 전용 저장소**: 학습자 저장소(예: glorious-purpose 로컬 클론)는 이 PC의 `backend/learning/sources.json`
  (Git 제외, 백업 제외) 또는 환경 변수 `DUVI_EVIDENCE_REPOS`(경로를 `;`로 구분, 예
  `DUVI_EVIDENCE_REPOS=C:\Users\<사용자>\glorious-purpose`)로 정한다. 코드에 기본 경로는 없다. Duvi는 파일을
  읽고 `git log`(고정 인자, 셸 없음, 5초 제한)와 JUnit XML 테스트 결과 파일을 읽기만 하며, 그 저장소에서
  코드를 실행하거나 쓰거나 push하지 않는다. 저장소 밖으로 나가는 경로·심볼릭 링크와 `.git` 안은 읽지 않는다.
- **돌아보기**: 왼쪽은 자기 완료 표시(이해나 숙달이 아님), 오른쪽은 기록이 보여 주는 근거 수(질문 기록 열린 질문/내
  설명, 확인 문제 근거 상태별, 커밋·테스트, 오늘 복습). 근거가 없으면 0 대신 "아직 증거 없음", 저장소가 없으면
  "설정된 저장소 없음"이라고 쓴다. 숫자는 변화 기록이지 점수가 아니다.
- **화면 모듈 연결**: `createLearningViewApi(request,{open,lectureName})`로 api를 만들고
  `renderQuizScreen(root,api,{lectureId,segmentId})`, `renderLectureQuizTab(root,api,{lectureId})`,
  `renderReviewScreen(root,api)`를 부른다. 스타일은 `src/quiz-view.css`, `src/review-view.css`.
  `node scripts/preview-views.mjs <폴더>`는 예시 데이터로 두 화면을 1536·1280 폭에서 찍는다.
