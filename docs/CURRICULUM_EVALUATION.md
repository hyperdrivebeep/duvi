### 3.2 그 밖의 빈틈

1. **3단계(ML과 검증)와 8단계(네 조건 비교 실습)에는 앱 영상이 없다.** 3단계는 Google MLCC 읽기 4개, 8단계는 Glorious 문서 7개다.

   **읽기 자료에 대한 질문은 앱에 저장할 수 없다.** (5절 4번)
2. **Stanford CS229 영상 3구간은 앱에서 재생할 수 없다.** 2026-11-17 YouTube oEmbed가 HTTP 401을 돌려줬다(삽입 재생 불가로 보임).
   그래서 외부 링크로 남긴 현재 처리가 맞다. 같은 영상의 세 구간이 `lectureId` 하나를 공유하면 완료 표시도 하나로 합쳐지므로(`resourceProgressId`),
   나중에 재생이 가능해져도 구간별 진행 ID를 먼저 정해야 한다.
3. **R-020 5.3의 "마이크로 발견기"(200줄 안팎으로 발견 루프를 직접 짜기)는 로드맵의 과제가 아니다.** 5D 과제(BIC 가중치·전분산·판별 측정)가 재료를 대부분 다루지만,

## 4. 이 학습자에게 맞는가 (적합성 리뷰)

전제: Python 초보, 주 10~12시간, 여러 기기, 53주 로드맵. 근거는 소스 읽기와 2026-11-17 격리 환경의 헤드리스 Chrome 관찰(1280px·390px)이다.
관찰한 흐름: 학습 로드맵 → 강의 폴더 준비 → Karpathy micrograd 열기(영어 자막 653문장 자동 준비) → 재생 → 00:07에 질문 저장 → 강의 완료 → 진행률 1/169.

### 잘 되는 것

- **첫 할 일이 분명하다.** 로드맵 첫 카드가 "MIT 1강 · print(2 + 3)을 실행하고 결과를 먼저 예상하라"를 보여 준다. 사이드바에도 "다음 · …"이 있다.
- **완료 표시가 한 번에 반영된다.** 강의 화면의 "강의 완료"가 사이드바(1/169), 로드맵 전체(1%), 단계(5단계 1/8)에 바로 반영됐고 취소할 수 있다.
- **질문이 시점과 원문에 묶인다.** 저장한 기록에 강의 ID·시간·당시 영어 원문·번역 스냅샷이 남고, 나중에 그 시점으로 돌아갈 수 있다.
- **처음 설명을 지우지 않는다.** 최초 설명·수정 이력·도움 정도를 보관하고, 복습은 이전 답을 펼치기 전에 먼저 떠올리게 한다.
- **진행률이 숙달을 뜻하지 않는다고 화면에 적혀 있다.** 시청 시간·AI 칭찬으로 통과시키지 않는다.

### 부족한 것 (우선순위 순)

1. **쌓인 질문을 다시 보기 어렵다.** 새 기록의 제목 칸에 강의 제목이 미리 들어가고, "내 기록" 카드는 질문 대신 설명을 본문으로 보여 준다.
   관찰: "Value 객체의 grad는 왜 처음에 0인가?"라고 저장했지만 목록에는 강의 제목과 설명만 보였다. 질문이 열 개만 넘어도 무엇을 물었는지 찾기 어렵다.
2. **휴대폰에서는 보면서 질문할 수 없다.** 390px에서 "질문 남기기"를 누르면 질문 패널이 영상 아래로 열리고 영상이 화면 밖으로 밀린다. 질문을 시작해도 재생이 멈추지 않는다.
3. **여러 기기 사이의 동기화가 없다.** 학습 기록은 PC마다 `backend/learning/state.json`에 따로 쌓이고, 옮기려면 JSON 백업을 내려받아 복원해야 한다.
   설계안은 [MULTI_DEVICE_SYNC.md](MULTI_DEVICE_SYNC.md).
4. **읽기 자료에 대한 질문을 저장할 곳이 없다.** 기록은 영어 자막이 있는 시점을 요구한다. 69개 읽기 자료와 3·5D·8단계 전체가 기록 밖에 있다.
5. **영상을 보기 전에 예측하도록 이끄는 장치가 약하다.** "결과를 먼저 예상하라"는 문구는 MIT 1강 카드에만 있다. 예측 칸은 "이 설명을 시험하기"를 펼쳐야 보인다.
6. **5D단계가 초보자에게 가파르다.** 3.1절 참고. 앱에서 볼 수 있는 해설 영상이 없다.
7. **주당 시간 계획이 보이지 않는다.** 단계는 "4주"로만 표시되고 자료별 예상 시간이 없다. 주 10~12시간 안에 들어가는지 학습자가 직접 계산해야 한다.
   (YouTube 자료는 처음 열기 전까지 길이 정보가 없다.)
8. **작은 화면의 표시 결함.** 390px에서 영어 자막 상자의 다섯째 줄이 글자 중간에서 잘려 보이고, 제목 입력칸 둘째 줄도 반쯤 잘린다.

## 5. 강의 중 질문(실시간 질문) 판정

**판정: 시청 중 질문을 남기는 기능은 있고 동작한다. 쌓인 질문을 다시 꺼내 공부에 쓰는 기능은 절반만 있다.**

비유하면 지금 Duvi는 **책갈피에 메모를 끼우는 것**은 잘 되지만, **메모들을 모아 "아직 못 푼 문제" 목록으로 정리하는 노트**는 아직 없다.

| 기능 | 상태 | 근거 |
|---|---|---|
| 시청 중 "질문 남기기"로 현재 시점 기록 | 있음, 관찰함 | 00:07 기록 저장, 원문 cue·번역 스냅샷 보관 (`src/learning-editor.mjs`) |
| 질문 한 줄만으로 저장 | 있음, 관찰함 | 설명·근거 칸은 선택 |
| 저장 직후 복습 예약 | 있음, 관찰함 | 새 기록 기본값 "1일 뒤", 목록에 다음 복습 날짜 표시 |
| 기록 목록·원래 시점으로 이동 | 있음 | "내 기록" 탭, "원문 시점 확인" |
| 복습 시 먼저 떠올리고 나서 이전 답 보기 | 있음(소스) | "복습" 탭은 예정일이 지난 기록만 표시. 오늘 저장한 기록은 내일부터 보인다 |
| 기록별 Markdown 내보내기 | 있음 | 기록 하나씩. 전체 묶음 내보내기는 없음(JSON 백업은 있음) |
| AI 튜터 `/api/learning/tutor` | 있음(소스), 이번에 실행 안 함 | 저장된 기록·원문 구간으로 힌트/비평/설명 요청. ChatGPT 연결 필요. 답변 전문은 저장하지 않음 |
| 목록에서 질문 문장 보기 | **없음** | 카드 본문은 설명, 제목은 기본값이 강의 제목 |
| 열린 질문 / 해결한 질문 구분 | **없음** | 상태 필드 없음 |
| 앞으로의 복습 일정 보기 | **없음** | 예정일이 지난 것만 보임 |
| 질문할 때 자동 일시정지 | **없음** | 직접 멈춰야 함 |
| 읽기 자료에 대한 질문 | **없음** | 자막 시점이 필수 |

**가장 작은 설계** (저장 형식 변경 없이, 프런트엔드 두 파일):

1. `src/learning-editor.mjs`: 새 기록의 `title`을 빈 값으로 둔다. 목록 제목은 이미 `title || question` 순서로 고른다.
2. `src/learning-records-view.mjs`: 카드에 질문을 먼저 보이고 설명은 그 아래에 둔다. 상단에 "전체 / 열린 질문" 전환을 둔다.
   "열린 질문"은 저장된 값에서 계산한다: `question`이 있고, `explanation`이 비었고, `reviews`가 없다.
3. 같은 화면에 "전체 기록 Markdown 내려받기"를 둔다. 기존 `recordMarkdown`을 이어 붙이면 된다.
4. 복습 탭에 "예정된 복습" 접힘 목록(예정일 오름차순)을 더한다. 기존 `reviewDueAt`으로 계산한다.

이 네 가지는 기존 테스트 파일(`tests/learning-ui.test.mjs`)에 순수 함수 테스트로 붙일 수 있다. 이번 PR에서는 구현하지 않았다.
UI 변경은 이 저장소 규칙상 1280px·390px 브라우저 확인을 다시 거쳐야 하므로 별도 작업으로 남긴다.
