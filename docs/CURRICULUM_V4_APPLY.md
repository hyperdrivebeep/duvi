## 호환 계약과 표시

- `learning-roadmap.mjs`의 기존 13개 `phase.id`는 `backend/learning-curriculum.mjs`의 폴더 키다. 기존 자료를 같은 단계·같은 상대 순서에 둔다. `lectureId` 공유 자료의 첫 번째 `resource.id`가 진행 키이고, 강의 헤더도 첫 일치 위치를 쓴다 (`learning-model.mjs`, `learning-ui.mjs`). 기존 저장 구조·폴더 순서·강의 위치는 바꾸지 않는다. 로드맵과 강의 재개 영역은 같은 **다음 할 일** 계산을 사용한다. 필수 단계 후속 과제를 해당 단계 자료 뒤에 안내하며, 뒤 단계에서 시작한 자료가 앞 단계의 필수 과제를 건너뛰게 하지 않는다.
- 복원된 v3 기록에서 5단계까지의 자료만 완료된 경우 먼저 `5단계 직접 수행 확인`을 안내한다. 1·3B의 확인과 3B 필수 카드가 남아 있으면 이어서 보완하도록 안내하며, 모두 충족하면 `E01 → 5B`로 이어진다. 확인은 자동 이관하지 않는다. 단계 안의 필수 카드는 편성 순서를 따르되, 8단계에서는 선수인 I-CAP을 E07보다 먼저 둔다.
- 헤더는 종전 `기존 자료 x/227` 및 단계별 기존 자료 집계를 유지하고, 나란히 전체 `필수 v4 a/10`과 해당 단계의 `필수 v4 a/n`을 표시한다. 단계 직접 수행 확인은 진입 조건이지 필수 카드 건수에 포함하지 않는다.
- 일반 읽기/실습은 `resource.id` 자체가 키다. `/api/learning/progress`와 로컬 저장소·백업/동기화는 이 키를 이용한다. 기존 키·강의 ID·URL을 변경하거나 마이그레이션하지 않는다. 새 ID는 `v4-` 접두사, 새 영상 강의 ID는 이전 자료와 겹치지 않는다. 확인된 공개 404는 원 URL·권한 안내 및 자기 완료 조작은 남기고 접근 불가 사유를 표기한다.
- 단계의 직접 수행 확인과 필수 카드 제목은 기존 단계 내용에 표시하고, 권장·선택만 별도 묶음에 접는다. 필수 카드 명세는 대기 중에도 읽을 수 있다. 단계 확인은 **앱 밖 직접 과제를 한 뒤 남기는 명시적인 자기 확인**이다. 기존 읽기·강의 완료는 그 확인으로 간주하지 않는다. 실습 fixture·채점기·실행기는 이 PR 범위가 아니며 UI에 표시한다.
- 개념 지도 생성기와 JSON은 기존 개념·자료 ID를 유지한다. v4 선택 경로를 추가하더라도 v1 역사적 판정이나 숙달의 증거로 표시하지 않는다. 내부 과제는 로드맵으로 이동하고 선수를 확인한다.
- 자동 검사는 기준판의 익명 합성 진행 fixture로 기존 키, 학습 활동, 완료, 다음 할 일, 분모, 첫 2주, 강의 위치를 비교한다. 롤백은 v4 코드만 되돌리며, 저장된 신·구 기록은 삭제하지 않는다.
- 검증 증거 정정: 최초 리뷰 대상 `bd0c4f9`에서는 `learning-sync.test.mjs`가 변경되지 않았다. 리뷰 후속 변경에서만 v4 진도의 양방향 동기화와 v3 화면에 없는 키를 보존하는 단일 기존 자료 편집, 백업 내보내기·가져오기 왕복 테스트를 추가했다.
