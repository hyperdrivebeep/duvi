# Duvi 확인 문제 설계 · 강의를 실험처럼 확인하기

작성일: 2026-11-22. 범위: **설계**(task-first-frontend 1–6단계). 구현(7–8단계)은 사용자가 시안을 고른 뒤에 한다.

사용자 요청(2026-11-22): "강의를 전부 번역하고 확인 문제 만들어 달라고 하면 문제 만들어 주는 기능은 아직 없지… 1번(확인 문제)이 내가 원하는 프로젝트에 도움이 되게 만들려면 어떡해야지. glorious purpose가 뭘 하는지 너도 알잖아."

핵심 과업은 **강의를 본 뒤 내가 정말 이해했는지 확인하되, 그 확인이 Glorious 연구자가 하는 일(예측 → 측정 → 설명 수정, 두 설명을 가르는 실험, 모르면 보류)의 연습이 되게 하는 것**이다.
성공하면 강의마다 검증된 확인 문제가 생기고, 내 예측·확신·실제 결과·바뀐 생각이 시간에 고정된 기록으로 남아 복습과 포트폴리오로 이어진다.

> 상태: 1–6단계 완료, **시안 선택 대기**. 제품 코드는 바꾸지 않았다.

## 1. 기준과 권한

- 저장소: github.com/hyperdrivebeep/duvi. 읽은 커밋 `origin/main` = **`5f42b61`**(2026-11-22 `git fetch`로 확인). 로컬 설치본도 같은 커밋이며 손대지 않았다. 설계는 별도 worktree(브랜치 `design/quiz-checks`)에서 했다.
- 승인 범위: 설계 문서와 시안 이미지를 이 폴더에 올린다(Duvi 작업 push 사용자 지시). 데스크톱만(모바일 제외 지시). 병합은 별도 검토자가 통과시킨 뒤에만 한다.
- 자료 성격: 강의 화면은 MIT OpenCourseWare 6.100L 1강 실제 캡처(CC BY-NC-SA 4.0). 영어 자막 한 줄은 실제 문장. **문제·답·시각·내 설명·개수는 모두 시안용 예시**다(실제 AI 생성이나 실행 결과가 아니다). 이미지에 계정·경로·실제 학습 기록은 없다.

## 6. Glorious Purpose와의 연결 — 무엇이 같은 모양인가

비유하면, Glorious 에이전트는 **실험실의 연구원**이고 확인 문제는 **연구원 수습 과정**이다. 에이전트가 세계에 대해 하는 일을 학습자가 강의 내용에 대해 작게 해 본다. 에이전트 자체를 학습시키는 것이 아니라 그 에이전트를 설계할 사람의 습관을 기른다.

| 문제 유형 | 학습자가 하는 일 | Glorious에서 같은 모양 | 근거 문서(Glorious) |
| --- | --- | --- | --- |
| 예측 | 코드 출력을 먼저 적고 확신을 고른 뒤 실행 | 예측 오차로 세계 모형을 고침 | NORTH_STAR "관찰과 행동의 결과로 세계 모형 발전" |
| 구별 실험 | 두 설명의 예측이 **다른** 입력을 고름 | 경쟁 가설을 가르는 측정 선택(능동 측정) | EXP-065, EXP-071 |
| 판단 보류 | "알 수 없음"과 더 필요한 정보를 답함 | 구별 측정이 없으면 주장하지 않고 유보 | EXP-066, CLAIMS(예측 동등 집합) |
| 원문 회상 | 강의가 실제로 한 말을 내 말로 | 출처와 내 추론, AI 제안을 구분 | DEC-009 |
| 가정 찾기(2단계) | 주장이 기대는 측정·선택·표현·해석 가정 찾기 | 측정·선택·표현·해석 가정 점검 | DEC-013 |

이 연결을 지키는 규칙:

1. **AI가 정답을 정하지 않는다.** 정답 근거는 실제 실행, 원문 인용, 사람 확인 중 하나여야 한다. AI만 정한 정답은 "AI 제안 · 정답 미검증"으로 표시하고 "검증된 문제" 수에 넣지 않는다(사용자 지시: 정답 라벨을 독립 검증 없이 AI가 정하지 않는다).
2. **점수·숙달 판정이 없다.** 시도 수, 예상과 다름, 보류가 정답이었던 문제 수만 보인다(기존 원칙: AI 긍정 판정이 숙달이 아니다).
3. **틀린 것을 숨기지 않는다.** 처음 예측과 처음 설명은 수정 이력에 그대로 남는다(실패를 숨기지 않는 실험 원장과 같은 원칙).
4. **포트폴리오로 이어진다.** 카드가 Markdown으로 나가며 "예측 → 실제 → 바뀐 생각 → 다음 구별 실험"이 읽힌다(사용자 지시 2026-11-22: 지식·문제 해결·실험 결과를 포트폴리오로 축적).
5. **개념 지도와 연결한다.** 문제마다 `CONCEPT_MAP.md`의 개념(예: 정수·실수 자료형)을 붙여 개념별로 "도움 없이, 시간을 두고 맞힌 적이 있는가"를 본다. 이 개념 지도는 Glorious 모델 설계에 필요한 160개 개념에서 왔다.

## 7. 정답 검증 계약

```text
[강의 대본(영어·한국어 정렬 문장)] → 구간 나누기(약 5~10분)
  → AI가 문제 초안 생성(JSON: 유형, 시각, 문제, 원문 인용, 코드, 예상 답, 개념)
  → 독립 확인
      코드 문제: Pyodide 작업자에서 실제 실행(시간 제한, 파일·네트워크 없음) → 정답 = 실제 출력
                 AI 예상 답과 다르면 AI 답을 버리고 실제 출력을 씀(불일치 기록)
      원문 문제: 원문 인용이 그 시각 구간 대본에 **글자 그대로** 있어야 통과, 없으면 버림
      판단 보류: 반례 두 개를 실행해 두 경우가 모두 가능함을 확인할 수 있으면 "실행 근거", 아니면 AI 제안
      그 밖: AI 제안 · 미검증
  → 문제 세트 저장(강의 ID, 대본 해시, 정렬 버전, 생성 모델, 프롬프트 버전, 검증 상태)
```

| 정답 근거 상태 | 표시 | 검증된 문제 수에 포함 |
| --- | --- | --- |
| `executed` | 정답: 실제 실행 결과 | 예 |
| `source_quoted` | 정답 근거: 원문 mm:ss 인용 확인 | 예 |
| `learner_confirmed` | 내가 확인함 | 예(내 판단으로 구분 표시) |
| `ai_unverified` | AI 제안 · 정답 미검증 · 채점은 내가 | 아니요 |
| `retired` | 이상한 문제로 신고됨(목록에서 뺌, 기록은 유지) | 아니요 |

**저장소 규칙과의 관계.** `AGENTS.md`는 "학습 행동으로 학습자 코드를 자동 실행하지 않는다"고, `LEARNING_DESIGN.md`는 "웹 페이지에서 임의 셸 실행을 추가하지 않는다"고 정한다. 그래서 기본 설계는 다음과 같다.

- 실행하는 코드는 **문제에 들어 있는 고정 코드뿐**이다. 문제를 만들 때 한 번 실행해 정답을 확정하고, 학습자가 "확인"을 누르면 저장된 결과를 보여 준다. 셸·파일·네트워크는 쓰지 않는다.
- 구별 실험은 학습자가 코드를 새로 쓰는 대신, **미리 실행해 둔 후보 입력 3~4개 중에서 고르는** 형식으로 한다(예: `6 / 3`, `7 / 2`, `4 // 2`). 고른 뒤 각 가설의 예측과 실제 결과를 보여 준다.
- 학습자가 직접 쓴 코드를 격리 환경에서 실행하는 기능은 위 규칙을 바꾸는 결정이라 **사용자 승인 전에는 만들지 않는다**(12절 질문).

대본이 바뀌면(번역 재정렬 등) 문제 세트는 "오래됨"으로 표시하고 다시 만들기를 제안한다. 이미 푼 기록은 당시 문제 스냅샷과 함께 남는다.

## 8. 데이터·동기화·준비 작업

- **문제 세트**: 번역처럼 강의별 생성 자산 `backend/quizzes/<강의>.json`. 여러 PC 동기화는 번역 동기화(`translation-sync.mjs`)와 같은 규칙(검증, 크기 제한, 준비 중 교체 금지)을 따른다.
- **푼 기록**: 학습 상태(`state.json`)에 `attempts` 추가(스키마 3). 문제 스냅샷·내 예측·확신·실제·설명·도움·다음 복습. 동기화는 기록과 같은 ID 단위 병합. 스키마 2 클라이언트는 `attempts`를 읽지 못하므로 두 PC 모두 새 버전이 필요하다(PR #12와 같은 경계).
- **복습 연결**: 틀렸거나 "확실했는데 틀림" → 1일, 맞았지만 확신 낮음 → 3일, 확실히 맞음 → 7일. 기존 1/3/7일 복습 목록에 함께 나온다.
- **준비 작업("전부 번역하고 문제 만들기")**: 폴더를 고르면 강의마다 `전체 번역 → 문제 초안 → 독립 확인` 순서의 작업 줄을 만든다. 중단·재시작·사용 한도 초과 뒤 이어 하기, 강의별 상태(`대기 / 준비 중 n% / 문제 n / 실패: 이유`). ChatGPT 계정 사용 한도를 쓰므로 예상 호출 수를 먼저 보여 준다.

## 10. 구조별 비교 시안

- **공통 사례**: MIT 6.100L 1강, 19:40, 같은 영어 자막, 같은 예시 문제 세트 9개(예측 3, 구별 실험 1, 판단 보류 1, 원문 회상 2, AI 제안 2), 같은 정답 근거 표시. 세 시안 모두 같은 내용을 쓰고 구조만 다르다.
- **만든 방법**: Duvi 실제 토큰(색·글꼴·간격·전체화면 어두운 면)으로 쓴 정적 HTML/CSS를 Bun.WebView(Chrome)로 캡처. 뷰포트 CSS px: 일반 1536×780·1280×720, 전체화면 1536×864. 9장 모두 가로 넘침 0(`scrollWidth = innerWidth`)과 패널 안 잘림 0을 스크립트로 확인. 동작하는 앱이 아니라 배치 시안이다.

### A. 강의 속 체크포인트

- 구조: 시간 띠에 ◆ 체크포인트(구간 끝). 도달하면 영상이 멈추고(끌 수 있음), 기존 "이 강의 · 시간순" 흐름에 문제 카드가 끼어든다. 답하면 이어서 재생.
- 장점: 새 화면 없음. B+ 구조를 그대로 씀. 강의 사이 시험이 딴생각을 줄인다는 근거(Szpunar 2013).
- 비용·위험: 흐름이 끊김. 380px 패널에서 긴 설명 쓰기가 불편. 문제를 강의 진행 순서로만 봄.
- 비교 과업: 1강 20분 시청 중 체크포인트 2개를 풀고 시청을 이어 가는 데 걸린 시간, 건너뛴 수.

### B. 강의 끝 확인 세트

- 구조: 강의를 다 보면 영상 자리가 문제 세트로 바뀐다(영상은 작은 썸네일). 왼쪽은 유형별 목록, 가운데는 한 문제씩 큰 카드. 오른쪽 패널에 다음 복습·신고·Markdown.
- 장점: "전부 번역하고 문제 만들어 줘"라는 요청과 가장 직접 맞음. 넓은 화면에서 예측·결과·설명을 한눈에. 유형별로 고르기 쉬움.
- 비용·위험: 시청과 분리(강의 직후에만 풀면 잊기 전 확인 효과는 줄 수 있음). 원문 장면은 칩을 눌러 이동해야 봄.
- 비교 과업: 강의 직후 9문제 세트를 끝내는 시간, "예상과 다름" 문제에 설명을 쓴 비율.

### C. 탐구 노트

- 구조: 문제 하나가 **실험 카드**. 단계: 예측 → 확신 → 실행 → 왜 달랐나 → 생각 수정·복습. 카드는 강의를 넘어 "탐구 노트"에 쌓이고 개념별로 모아 보며, 그대로 포트폴리오 Markdown이 된다. 전체화면에서는 장면에서 카드를 시작만 한다.
- 장점: Glorious 실험 원장(가설·판별 실험·결과·수정)과 같은 형식이라 연구 습관과 포트폴리오에 가장 직접적. 처음 생각과 바뀐 생각이 남음.
- 비용·위험: 한 문제에 드는 시간이 가장 김. 초보에게 단계가 무거울 수 있음. 새 화면(탐구 노트)이 하나 늘어남.
- 비교 과업: 카드 3장을 끝까지 쓰는 시간, 일주일 뒤 포트폴리오 Markdown만 보고 무엇을 배웠는지 설명할 수 있는지.

### 권고: B를 뼈대로, 문제 하나는 C의 카드 방식으로

- 사용자가 원한 흐름("강의를 전부 번역하고 확인 문제를 만들어 달라")은 B의 **준비 → 세트**와 가장 잘 맞는다.
- 문제 하나를 풀 때는 C의 **예측 → 확신 → 확인 → 왜 달랐나**를 쓴다. 이것이 Glorious의 예측 오차·판별 실험·보류 연습이고 포트폴리오가 된다.
- A의 체크포인트는 같은 문제 세트를 강의 중에 보여 주는 **선택 옵션**으로 나중에 붙인다(데이터가 같아서 화면만 추가하면 됨).
- 구현 순서 제안: ① 준비 작업과 문제 세트 생성·독립 확인(코드 실행 포함) ② B 세트 화면 + C 카드 흐름 ③ 복습·동기화·포트폴리오 내보내기 ④ A 체크포인트 옵션.

## 12. 한계

- 학습 효과 근거는 다른 집단·다른 과목 연구다. Duvi에서 효과를 잰 적 없다.
- AI 문제 초안 품질과 실제 호출 수·비용은 측정하지 않았다(ChatGPT 연결 상태에서 1강으로 시험 필요).
- Pyodide로 실행할 수 없는 문제(파일·네트워크·외부 패키지)는 코드 문제로 만들지 않는다.
- 강의가 Python이 아닌 경우(수학·통계)는 코드 실행 대신 계산 확인(작은 수식 평가)이나 원문 인용만 가능하다. 분야별 확인 방법은 구현 단계에서 정한다.
- 시안 이미지는 정적 배치이며 실제 동작·키보드·스크린리더는 확인하지 않았다.
- 열린 결정: 학습자가 직접 쓴 Python 코드를 격리 실행(Pyodide)해도 되는가. 허용하면 구별 실험에서 원하는 입력을 직접 넣어 볼 수 있지만, 저장소 규칙(학습자 코드 자동 실행 금지)을 바꾸게 된다.
