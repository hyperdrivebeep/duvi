# B+ 학습 화면 구현 전후 비교 (2026-11-21)

[← QA 증거 목록](../README.md) · 설계: [B+ 권고안](../../design/2026-11-19-notebook-ui/README.md)

## 무엇을 확인했나

사용자가 고른 B+ 시안(큰 영상 + 시각 띠 + "이 강의 · 시간순" + 인용 미리보기 + 질문 아래 내 설명 + 쓰기 시작한 시각)을 실제 Duvi에 넣고, 같은 자료로 **바꾸기 전(main d5feeff)** 과 **바꾼 뒤(feat/bplus-study-layout)** 를 나란히 찍었습니다. 사용자가 핵심이라고 한 **전체화면**을 1280·1536 크기에서 봤습니다. 데스크톱만 봤습니다.

## 어떻게 확인했나

- 브라우저: 임시 프로필을 쓰는 헤드 있는 Chrome 157(GPU 끔)을 omowright로 조종했습니다. 버튼·마커·시각 칩은 CDP 마우스 클릭과 키 입력으로 눌렀습니다.
- 진짜 전체화면: 전체화면 버튼을 실제로 클릭해 `document.fullscreenElement`가 `#stage`가 된 것을 매번 확인했습니다. 자동화 창에서는 Chrome이 요청을 거절("not granted")해서, QA 주소(127.0.0.1:6121/6122)에만 Chrome의 전체화면 권한을 CDP로 허락한 뒤 클릭했습니다. 1280·1536 크기는 그 상태에서 화면 크기 에뮬레이션으로 맞췄습니다.
- 상태: 저장소 작업트리 두 개(전/후), 빈 `LOCALAPPDATA`, 사용하지 않는 포트(6121·6122)의 별도 서버, `DUVI_CHAT_MOCK=1`(QA 전용 모의 답변)을 썼습니다. 평소 쓰는 6103 서버와 계정 보관소는 건드리지 않았습니다.
- 자료: 두 쪽에 똑같이 넣은 예시 대화 1개(질문 2개)와 기록 2개(하나는 내 설명 있음, 하나는 열린 질문). 모두 "[QA 예시]"가 붙은 가짜 문장입니다. 한국어 자막은 "[QA 합성]"이 붙은 자리 문장으로, 실제 번역이 아닙니다.
- 이미지: PNG를 품질 80 WebP로 바꿨습니다(원본이 1600px보다 작아 크기는 그대로). 두 화면의 글자와 속성값에서 PC 이름, 로컬 경로, 이메일을 찾아봤고 없었습니다.
- 측정 원자료: [before-measurements.json](before-measurements.json), [after-measurements.json](after-measurements.json) (영상·자막·패널·시각 띠의 위치와 크기, 재생 시각).

## 자동 검사

`npm test` 158개 통과(빌드 포함). 새 검사: 시간순 흐름·필터·지금 선·시각 띠 구간·마커(`tests/learning-ui-stream.test.mjs`), 쓰기 시작 시각·보낼 자료 선택, 보낼 자료를 끄면 서버가 실제로 대본·노트를 빼고 예전 요청은 둘 다 보냄(`backend/tests/learning-chat.test.mjs`), 채팅 답 아래 내 설명이 AI 답과 따로 기록에 저장되고 다른 PC와 병합해도 유지됨(`backend/tests/learning-chat-storage.test.mjs`).

## 확인하지 않은 것

- 실제 ChatGPT 답변(모의 공급자만 사용). 실제 답에 `[mm:ss]`가 얼마나 자주 나오는지도 모릅니다.
- 사람 사용성: 인용 미리보기·시각 띠가 실제로 더 빨리 이해되는지는 사람 시험이 필요합니다.
- 실제 번역 문장으로 본 인용 카드(한국어는 QA 자리 문장).
- 모니터 전체를 덮는 OS 수준 전체화면(에뮬레이션 크기로 확인), YouTube 영상 강의(MIT mp4만 봄), 휴대폰.

## 병합 후 독립 검토와 수정

[병합본 검토표](REVIEW.md)에 수정 전 코드 위치와 영향을 적었습니다. 아래는 강의 1·2와 모의 기록을 쓰는 별도 서버에서 촬영한 화면입니다. 1강 01:12에서 질문을 쓰고 2강을 연 뒤 1강으로 돌아왔습니다.

| 확인한 동작 | 화면 |
|---|---|
| 수정 전에는 2강 입력칸에 1강 질문이 보였습니다. 수정 후에는 2강 입력칸이 비어 있고, 1강으로 돌아오면 원래 문장과 01:12가 남습니다. | [전](review-before-lecture2.webp) · [후](review-after-lecture2.webp) · [1강 복귀](review-after-returned.webp) |
| 설명을 쓰는 도중 같은 기록에 다른 수정이 들어오면 두 문장을 비교할 수 있습니다. 비교 후 저장을 눌러야 서버의 설명이 바뀝니다. 상대 수정은 QA 저장소에 별도 쓰기로 재현했습니다. | [비교](review-after-compare.webp) · [저장](review-after-resolved.webp) |
| 질문을 쓴 채 Chrome에서 실제 전체화면 버튼을 눌렀습니다. `document.fullscreenElement`는 `#stage`였고 영상·시각 띠·영어·한국어 영역이 서로 겹치지 않았습니다. | [1280×720](review-after-fs-1280.webp) · [1536×864](review-after-fs-1536.webp) |

두 PC의 동시 질문은 저장소 테스트에서 양쪽 순서로 병합한 뒤 백업·복원해서 각 답이 자기 질문에 연결되는지 확인했습니다. 물리적으로 PC 두 대에서 시험하지는 않았습니다. `npm test`는 수정본에서 161개가 한 번에 통과했고 `npm run build`도 별도로 통과했습니다. 이 검토의 Chrome 화면에는 모의 기록과 표시용 한국어 자막을 썼습니다. 공개 MIT 강의 MP4 두 편을 임시 폴더에 내려받아 로컬에서 재생했습니다. QA 서버의 영상 출처 허용 목록에 그 로컬 주소를 추가했고, 영상 프레임이 준비되고 탐색이 끝난 뒤에 캡처했습니다. 제품의 영상 출처 설정은 그대로입니다.
